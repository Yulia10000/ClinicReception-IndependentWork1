# Журнал рішень команди

## 1. Мова програмування
Для розробки проєкту ClinicReception використовується мова C#.

## 2. Стиль іменування
Для класів і методів використовується PascalCase, для локальних змінних і параметрів — camelCase, для приватних полів — _camelCase.

## 3. Форматування коду
Для відступів використовуються чотири пробіли. Відкривні фігурні дужки розміщуються з нового рядка.

## 4. Організація коду
Кожен клас розміщується в окремому файлі. Методи повинні виконувати одну основну задачу.

## 5. Перевірка даних
Для методів передбачено перевірку вхідних аргументів. Особливу увагу приділено перевірці дат і часових інтервалів запису пацієнтів.

## 6. Автоматична перевірка
Для контролю стилю коду використовуються .editorconfig, StyleCop.Analyzers та вбудовані аналізатори .NET.

## 7. Придушення правил
Придушення діагностичних правил дозволяється лише з письмовим обґрунтуванням у .editorconfig або за допомогою атрибута SuppressMessage із заповненим полем Justification.

## 8. Перевірка перед комітом
Перед збереженням змін виконуються команди dotnet format --verify-no-changes та dotnet build -warnaserror.

## 9. Перехід на єдиний стандарт перевірки коду
Дата: 10.11.2026
Номер рішення: ADR-009

Вирішено використовувати єдиний чекліст ручного огляду коду та порівняти внутрішній стандарт із рекомендаціями Microsoft Learn і dotnet/runtime. Автоматичні перевірки не дублюються в чеклісті, оскільки вони виконуються аналізаторами.

## 10. Порядок внесення змін до стандарту
Дата: 10.11.2026
Номер рішення: ADR-010

Вирішено запровадити процедуру внесення змін до стандарту через письмові пропозиції, обговорення та фіксацію результатів у журналі рішень. Для версій стандарту використовується семантичне версіювання. Наявний код поступово приводиться до нових вимог, а шкідливі правила можуть бути скасовані після повторного розгляду.
