# Стандарт кодування та довідник конструктивних практик команди

## 1. Загальні положення

### 1.1. Сфера дії

Цей стандарт визначає правила написання, оформлення та перевірки програмного коду мовою C# для проєкту ClinicReception.

Проєкт ClinicReception призначений для запису пацієнтів на прийом до лікаря. Під час розробки використовуються об'єктно-орієнтований підхід, класи, методи, властивості та інші можливості мови C#.

Стандарт поширюється на всіх учасників команди, які створюють або змінюють програмний код проєкту. Його вимоги застосовуються до нових файлів, змінених частин програми та коду, який проходить перевірку.

Основна мета стандарту — зробити програмний код зрозумілим, однаково оформленим і зручним для подальшої підтримки. Дотримання єдиних правил допомагає уникати помилок, спрощує спільну роботу та полегшує пошук проблем у програмі.

### 1.2. Рівні обов'язковості

У стандарті використовуються чотири рівні обов'язковості правил:

- ОБОВ'ЯЗКОВО — правило потрібно виконувати в кожному випадку. Порушення такого правила не допускається.
- РЕКОМЕНДОВАНО — правило бажано виконувати, оскільки воно покращує якість і зрозумілість коду.
- ДОПУСКАЄТЬСЯ — правило можна використовувати за потреби, якщо це не погіршує структуру програми.
- ЗАБОРОНЕНО — використання такого підходу не допускається в межах проєкту.

Обов'язкові правила перевіряються під час перегляду коду, а частина з них додатково контролюється автоматичними аналізаторами.

### 1.3. Нумерація правил

Кожне правило має унікальний номер, який складається з літери категорії та порядкового номера.

Використовуються такі категорії:

- N — правила іменування;
- F — правила форматування;
- C — коментарі та документація;
- D — типи даних і змінні;
- S — керувальні конструкції та складність коду;
- A — автоматична перевірка;
- X — додаткові правила варіанта завдання.

Наприклад, N-01 означає перше правило іменування, F-01 — перше правило форматування, а X-01 — перше спеціальне правило варіанта.

### 1.4. Шаблон запису правила

Для кожного правила використовується однакова структура:

1. Ідентифікатор правила.
2. Назва правила.
3. Рівень обов'язковості.
4. Опис вимоги.
5. Обґрунтування.
6. Приклад правильного використання.
7. Приклад неправильного використання.

Такий шаблон допомагає однаково описувати всі вимоги та швидко знаходити потрібну інформацію.

### 1.5. Глосарій

Стандарт використовує такі основні поняття:

- Ідентифікатор — назва змінної, методу, класу або іншого елемента програми.
- PascalCase — стиль написання назви, у якому кожне слово починається з великої літери.
- camelCase — стиль написання назви, у якому перше слово починається з малої літери, а наступні — з великої.
- Метод — частина класу, яка виконує певну дію.
- Властивість — елемент класу для отримання або зміни значення.
- Аналізатор коду — інструмент, який перевіряє програмний код і повідомляє про можливі помилки або порушення правил.
- Рефакторинг — зміна внутрішньої структури коду без зміни його основної поведінки.
- Часовий інтервал — проміжок часу між початком і завершенням певної події.
- Часовий слот — визначений проміжок часу, протягом якого пацієнт може бути записаний на прийом.
