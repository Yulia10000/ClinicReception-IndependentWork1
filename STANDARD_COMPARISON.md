# Порівняння стандартів кодування

Для порівняння використано рекомендації Microsoft Learn та правила оформлення коду репозиторію dotnet/runtime. На їх основі визначено правила, які застосовуються в проєкті ClinicReception.

## Таблиця порівняння

| Приватні поля | camelCase, для приватних полів використовується `_` | `_camelCase`, для статичних полів `s_` | `_camelCase`, для статичних полів `s_` | Такий запис допомагає відрізняти поля класу від локальних змінних. |

## Відмінності нашого стандарту від публічних рекомендацій

### 1. Обов'язкове використання фігурних дужок

У нашому стандарті фігурні дужки обов'язкові навіть тоді, коли умовна конструкція містить лише один оператор. У dotnet/runtime допускається їх пропуск у деяких простих однорядкових конструкціях. Ми обрали суворіше правило, оскільки в навчальному проєкті код часто доповнюється новими операторами, а наявність дужок допомагає уникнути помилок під час таких змін.

### 2. Обмеження довжини рядка до 100 символів

У нашому стандарті встановлено максимальну довжину рядка 100 символів. У dotnet/runtime немає загальної жорсткої межі, а рекомендації Microsoft щодо коротших рядків стосуються насамперед прикладів документації. Ми встановили власну межу, щоб довгі вирази не ускладнювали читання та перегляд коду в редакторі.

### 3. Обмеження використання var

У нашому стандарті var дозволяється використовувати тоді, коли тип змінної явно зазначений у правій частині виразу, наприклад під час створення нового об'єкта. Microsoft Learn допускає var у ширшому випадку, коли тип можна зрозуміти з виразу. Ми обрали суворіше правило, щоб початківцям було легше визначати типи змінних під час читання коду.

### 4. Використання file-scoped просторів імен

У нашому стандарті для нових файлів рекомендовано використовувати file-scoped простори імен. Це узгоджується з рекомендаціями Microsoft Learn. Такий підхід зменшує вкладеність коду та робить файли компактнішими.
